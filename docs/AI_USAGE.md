# Отчет об использовании AI

В ходе работы над проектом активно использовался LLM-ассистент в качестве спарринг-партнера и генератора boilerplate-кода.

## На какие задачи привлекался AI:
1. **Генерация Boilerplate-кода и моков:**
   - Написание структуры Python-пакетов, создание базовых классов (`SafetyRouter`, `HybridRetriever`).
   - Написание скрипта `main.py` для тестирования пайплайна на CSV-датасете.
2. **Создание синтетических данных:**
   - Генерация репрезентативного датасета `tickets_sample.csv` для тестирования различных краевых сценариев (угрозы, слишком короткие сообщения, типовые вопросы).
3. **Оформление документации:**
   - Помощь в форматировании Markdown-файлов и генерация кода для Mermaid-диаграммы.

## Критический пересмотр предложений AI (Где я менял решения нейросети):
- **Архитектурный пивот:** Изначально LLM предложила наивную монолитную архитектуру — отправлять абсолютно каждый входящий тикет напрямую во внешний API (YandexGPT/OpenAI) для одновременной классификации и генерации ответа. 
- **Почему я это отклонил:** Я понял, что такой подход полностью провалит SLA при пиковых нагрузках (задержки внешних API), выйдет за рамки юнит-экономики (150₽ на пользователя) и не позволит мгновенно отсекать риски (PII, суды).
- **Мое решение:** Я спроектировал каскадную архитектуру (жесткое разделение на быстрый синхронный *Safety Router* на эвристиках/легком ML и медленный асинхронный *RAG-контур*). После этого я поручил AI переписать код заглушек уже строго по моему дизайну.
- **Исправление багов логики:** LLM генерировала правила безопасности по полным словам (например, поиск точного совпадения "прокуратура"). На этапе тестирования я выявил падение метрик из-за падежей и заставил переписать логику на стемминг (поиск по корням).

## Итог
Нейросеть отлично справилась с рутиной (генерация данных, структура классов, маркдаун), но ключевые архитектурные и продуктовые решения (разделение потоков, SLA, безопасность) пришлось проектировать и контролировать самостоятельно.
